## 1. OmniStack Context (OVERRIDES EVERYTHING BELOW)

These project-specific rules take precedence over any generic guidance:

| Rule | Detail |
|------|--------|
| **Base UI, NOT Radix** | shadcn/ui here uses Base UI primitives. ❌ NEVER use `asChild` — it's a Radix-only API. ✅ Compose via `render` prop: `<Button render={<a href="/docs" />}>Docs</Button>`, or style directly with `buttonVariants({ variant })`. |
| **Semantic tokens only** | `bg-background text-foreground`, `bg-muted text-muted-foreground`, `bg-primary text-primary-foreground`, `bg-destructive`, `border-border`. ❌ No raw hex (`bg-[#ff0000]`), no hardcoded `bg-white text-black` without `dark:` pairing. |
| **Server Components default** | `"use client"` only for hooks/events/browser APIs. Push client components to leaf nodes. |
| **Path alias `@/`** | Never relative imports like `../../components`. |
| **Named exports** | `export function ProjectCard()` not `export default`. |
| **`cn()` helper** | All conditional classes via `cn()` from `@/lib/utils`. |
| **Never edit `components/ui/`** | Generated by shadcn CLI. Wrap instead. |
| **Page-specific components** | Live in `app/(group)/route/_components/`. Shared ones in `components/`. |
| **Icons** | Lucide React for UI; react-icons/si for brand logos only. ❌ No emoji as icons. |
| **Mock auth & RBAC** | Data via `lib/mock-data.ts`; use helpers (`getMockProjectsByUser`, `roleAtLeast`) — don't filter manually on `user.role`. |
| **Dark mode** | Every styling change must work in light AND dark. Test both. |

## 2. When to Apply

Apply for: designing new pages, creating/refactoring UI components, choosing color/typography/spacing/layout systems, reviewing UI for UX/accessibility/consistency, implementing navigation/animation/responsive behavior, improving perceived quality.

Skip for: backend logic, API/database design, non-visual performance work, infrastructure/DevOps.

## 3. Rule Categories by Priority (1→10)

Work through priorities in order when building or reviewing UI:

| # | Category | Impact | Must Have | Anti-Patterns (Avoid) |
|---|----------|--------|-----------|----------------------|
| 1 | **Accessibility** | CRITICAL | Contrast ≥ 4.5:1 body text; alt text on meaningful images; complete keyboard nav with visible focus rings; `aria-label` on icon-only buttons; sequential heading hierarchy h1→h6; `role="alert"`/aria-live for errors; skip links on nav-heavy pages; labels tied to every input | Removing focus outlines without replacement; icon-only buttons without accessible names; color as the only state indicator; skipping heading levels |
| 2 | **Touch & Interaction** | CRITICAL | Web targets ≥ 24×24 CSS px (WCAG 2.2 AA); iOS 44pt / Android 48dp native guidance; ≥ 8px gap between targets; loading feedback on all async actions; click/tap primary (hover never required); pressed/active/disabled states visible | Hover-only interactions; instant 0ms state changes; double-submittable buttons; tightly packed clickables |
| 3 | **Performance** | HIGH | WebP/AVIF images sized correctly; lazy-load below-fold; reserve space (aspect-ratio, skeleton dimensions matching content) so CLS < 0.1; route-based code splitting; `transform`/`opacity` only for animation | Animating width/height/top/left; layout thrashing; content popping in without reserved space; badge/validation insertion pushing layout |
| 4 | **Style Selection** | HIGH | Match product type (see §5 Reasoning Profiles); one coherent style system; SVG icons only | Mixing flat & skeuomorphic randomly; emoji as icons; AI purple/pink gradients where inappropriate (finance/dev tools) |
| 5 | **Layout & Responsive** | HIGH | Mobile-first breakpoints (`md:` `lg:` `xl:` enhance up); test 320/375/414/768/1024/1440; no horizontal scroll; `min-h-dvh` not `h-screen` on mobile; text max-width 65–75ch; z-index scale system (10/20/30/50) | Fixed px container widths; disabled zoom; `z-[9999]`; desktop-first design; wide tables without `overflow-x-auto` wrapper or card fallback |
| 6 | **Typography & Color** | MEDIUM | Body ≥ 16px mobile / base 16px; line-height 1.5–1.75 body; modular type scale (12/14/16/18/24/32); clear heading vs body distinction; dark-on-light contrast | Text < 12px body; gray-on-gray; arbitrary font sizes; headings same size as body |
| 7 | **Animation** | MEDIUM | Motion duration context-aware (platform/component/user preference — no universal cutoff); decelerate on entry, accelerate on exit, linear for steady progress; motion conveys meaning; animate 1–2 key elements max per view; honor `prefers-reduced-motion`; cancelable transitions that set final semantic state directly (never depend on `transitionend` for correctness) | One duration copied everywhere; infinite decorative animations; scroll-jacking/parallax without reduced-motion fallback; enabling controls inside `animationend` |
| 8 | **Forms & Feedback** | MEDIUM | Visible label per input (never placeholder-only); inline error per field connected via `aria-describedby` + keyboard-findable error summary at top after failed submit; validate on blur; correct `type`/`inputmode`/`autocomplete`; loading → success/error submit feedback; password visibility toggle; auto-populate previously entered data | Placeholder-only labels; errors shown only at top without field links; silent failures; blocking paste in password fields; requiring re-entry of same info |
| 9 | **Navigation** | HIGH | Predictable back behavior; bottom nav ≤ 5 items (mobile); URL reflects state (deep-linking); active nav item visually indicated; breadcrumbs at 3+ depth levels; sticky nav doesn't obscure content (padding compensation) | Broken back button; overloaded nav; static URLs for dynamic views; nav overlapping first section |
| 10 | **Charts & Data** | LOW | Legends + tooltips on all charts; accessible color pairs; meaning never by color alone (patterns/labels too) | Ornate decoration over clarity; no filtering on large datasets |

### WCAG 2.2 Highlights (web, frequently missed)

- **Focus Not Obscured**: offset sticky headers with `scroll-padding-top: var(--header-height)`; dismiss persistent overlays covering focus.
- **Target Size (Minimum)**: 24×24 CSS px minimum, or spacing equivalent.
- **Dragging Movements**: every drag-only operation needs buttons/menu alternative (e.g., Move up/Move down beside drag handle).
- **Accessible Authentication**: allow paste + password managers (`autocomplete="current-password"`); offer passkeys/OAuth. ❌ `onpaste preventDefault`.
- **Text Reflow**: text must survive narrow widths, zoom, and user spacing overrides — fluid sizes, unitless line-height, content-driven height. ❌ fixed-width/fixed-height clipping boxes.
- **Long Tokens**: URLs/IDs wrap safely via `min-inline-size: 0; overflow-wrap: anywhere` on flex/grid text children.
- **Compact Labels (chips/badges)**: badge = static status `<span>` (not clickable div); interactive chip = native `<button aria-pressed>` with visible focus; collections wrap or use operable `+n` disclosure; keep label whole when practical, unavoidable truncation needs an accessible full-value path (not hover-only tooltip). Live count changes announce contextual status (`"3 items in cart"`) via one atomic `role="status"` — never a bare number.

## 4. Design System Generation Methodology

For any new page/project or system-wide visual direction, reason through this pipeline before writing code:

```
User request → Product type match → Pattern → Style → Colors → Typography
→ Effects → Anti-patterns to avoid → Pre-delivery checklist
```

**Step 1 — Analyze the request:** extract product type (SaaS/dashboard/tool/portfolio…), target audience & usage context, style keywords (minimal/playful/dark/immersive…), and confirm stack (here always: Next.js 16 + Tailwind v4 + Base UI).

**Step 2 — Match the product type** against the Reasoning Profiles (§5) to get pattern, style priority, color mood, typography mood, effects, and anti-patterns.

**Step 3 — Tune with Design Dials** (mental sliders 1–10):

| Dial | Low (1–3) | Mid (4–7) | High (8–10) |
|------|-----------|-----------|-------------|
| Variance | Centered/minimal (Minimalism bias) | Balanced/modern | Bold/asymmetric (Brutalism/Bento bias) |
| Motion | Subtle micro-interactions | Standard scroll/stagger | Complex choreography (pin, flip, split-text) |
| Density | Spacious (24–96px scale) | Standard (16–64px) | Dense dashboard (8–32px) |

**Step 4 — Output a complete design spec** in this shape before implementing:

```
TARGET: <name> — RECOMMENDED DESIGN SYSTEM
PATTERN:    <layout structure + section order>
STYLE:      <primary style + keywords> (perf cost / a11y risk noted)
COLORS:     Primary / Secondary / CTA / Background / Text (+ semantic token mapping)
TYPOGRAPHY: <pairing + mood>
EFFECTS:    <key effects + timing>
AVOID:      <anti-patterns for this industry>
```

Map generated colors onto OmniStack semantic tokens (`--primary`, `--accent`, …) in `app/globals.css` — never hardcode hex in components.

## 5. Product Reasoning Profiles (OmniStack-relevant)

| Product Type | Pattern | Style Priority | Color Mood | Typography | Key Effects | Avoid |
|--------------|---------|---------------|------------|------------|-------------|-------|
| **SaaS (general)** — OmniStack landing/marketing | Hero + Features + CTA | Glassmorphism + Flat Design; Minimalism if UX-focused; Glassmorphism if data-heavy | Trust blue + accent contrast | Professional + hierarchy | Subtle hover (200–250ms), smooth transitions | Excessive animation; dark mode by default |
| **Micro SaaS** | Hero-centric + trust | Motion-driven + vibrant block-based | Bold primaries + accent | Modern + energetic | Scroll-triggered + parallax | Static design; poor mobile |
| **Developer Tool / PaaS console** | Minimal + documentation | Dark Mode (OLED) + Minimalism/Swiss | Dark syntax theme + blue focus | Monospace accents + functional | Syntax highlighting, command palette | Light mode default; slow perf |

## 7. Stack Implementation Rules (Next.js 16 + Tailwind v4 + Base UI)

### Routing & Rendering

- App Router, file-based routing; colocate page-specific files in `_components/`; route groups `(name)` don't affect URL.
- Route-level `loading.tsx` and `error.tsx` (with `reset`) — not try/catch per component, not manual useState loading for routes.
- Server Components default; `'use client'` explicit and pushed to leaves. Stream slow fetches with `<Suspense>`.
- Fetch in async Server Components — ❌ `useEffect` for initial data.
- Choose strategy deliberately: SSG static / SSR dynamic / ISR semi-static.

### Data & Mutations

- Server Actions for form mutations: `<form action={serverAction}>`; **validate + authorize input in every Server Action** (they're public endpoints).
- Next.js 16 cache model: `cacheComponents`, `use cache` directive, `cacheLife('days')` profiles, `cacheTag('posts')` tags, `updateTag` for immediate read-your-own-writes, `revalidateTag(tag, "max")` for SWR semantics. Single-arg `revalidateTag` is deprecated.
- `proxy.ts` replaces middleware (nodejs runtime; no fetch-cache options there); configure specific `config.matcher`.

### Assets

- Always `next/image` with width+height (or `fill` + object-cover) to prevent CLS; `priority` only for LCP hero image; whitelist remote domains via `remotePatterns`.
- Fonts: self-hosted variable font in root layout (project uses Geist via setup — rely on `font-sans` class).

### Components (shadcn/ui v4 on Base UI)

- Add components ONLY via CLI: `npx shadcn@latest add <component>`; inspect with `--dry-run`/`--diff` before overwriting customized ones.
- Theming: OKLCH CSS variables in `globals.css` exposed to Tailwind v4 via `@theme inline`; complete `:root` + `.dark` schemes; pair each surface token with its foreground (`--primary` ↔ `--primary-foreground`).
- Use variant/size props (`<Button variant="destructive" size="lg">`), compose compound components (`Card > CardHeader > CardContent`), extend via `className` — never edit source.
- Controlled overlays: `open` + `onOpenChange`; dialogs need `DialogTitle`/`DialogDescription`; destructive confirms use `AlertDialog` with Action/Cancel; side panels use `Sheet side="..."`.
- Forms: React Hook Form + `Controller` + `Field`/`FieldLabel`/`FieldError` primitives (or TanStack Form adapters); Zod schema validation.
- Toasts: Sonner — `toast.success()/toast.error()`, `<Toaster />` once in root layout.
- Tables: `Table` structure with TableHeader/TableBody; complex needs → TanStack DataTable pattern.
- Skeletons match loaded-content dimensions (no generic spinners for content).
- Charts: `ChartContainer` + `chartConfig` theming + `ChartTooltip` — no inline colors, no bare Recharts Tooltip.
- Sidebar: wrap app in `SidebarProvider`, include `SidebarTrigger` for mobile.
- Import components individually from their files (tree-shaking).

### Security (UI-adjacent)

- Sanitize/escape all user-controlled data before render — ❌ `dangerouslySetInnerHTML` with user input.
- Configure CSP headers; `NEXT_PUBLIC_` prefix only for truly client-safe vars; secrets in `.env.local` (gitignored).

## 8. Workflow

1. **Classify the task**: new page/system direction → §4 full design-system reasoning; targeted component bug → relevant category in §3 + §7; polish/review → run §9 checklist; animation work → `references/motion-presets.md`.
2. **Pick the landing pattern first** (new marketing/docs pages): match intent against the pattern table in `references/landing-charts-typography.md` — section order IS the pattern. OmniStack signatures: Pricing Page + CTA (PaaS tiers), FAQ/Documentation (API portal), AI-Driven Dynamic Landing (AI Architect), Trust & Authority (infra).
3. **Generate the design spec** (§4 Step 4 output format) for anything visual-new; map results to OmniStack tokens.
4. **Check anti-patterns** for the matched profile (§5) explicitly before coding.
5. **Implement** following §7 stack rules + AGENTS.md conventions (they override everything here). Charts: consult chart-type mapping in references before choosing viz.
6. **Pre-delivery check** (§9). State clearly when guidance came from built-in defaults rather than a matched profile.

## 9. Pre-Delivery Checklist

```
[ ] Accessibility: contrast 4.5:1+ (both modes) · alt text · keyboard-complete with visible focus ·
    aria-labels on icon-only buttons · role="alert"/live regions for dynamic errors/status ·
    prefers-reduced-motion honored
[ ] Interaction: cursor-pointer on clickables · hover/active/disabled/loading states ·
    no hover-only functionality · async actions show feedback & block double-submit ·
    destructive actions confirmed (AlertDialog)
[ ] Layout: no horizontal scroll at 320px+ · reserved space (CLS < 0.1) · sticky offsets ·
    z-index scale respected · responsive at 375/768/1024/1440 · tested light AND dark mode
[ ] Content resilience: essential text reflows without clipping · long tokens wrap safely ·
    chips/badges wrap or disclose overflow · truncation always recoverable accessibly ·
    empty states helpful · dates/numbers locale-formatted
[ ] Forms: visible labels · inline field errors linked via aria-describedby ·
    error summary focusable after failed submit · correct type/inputmode/autocomplete ·
    submit shows loading → success/error
[ ] Performance: next/image everywhere with dimensions · lazy below-fold ·
    code-split heavy components (charts, dialogs) · font-display swap
[ ] OmniStack compliance: semantic tokens only · cn() · @/ aliases · named exports ·
    no asChild (Base UI render prop / buttonVariants instead) · components/ui untouched ·
    mock-data helpers used for RBAC
[ ] Icons are SVG (Lucide/react-icons) — zero emoji-as-icon
[ ] Charts: correct type for the data question · legend + tooltip (keyboard-accessible) ·
    skeleton while loading · error state with retry · empty state with guidance ·
    semantic chart colors via chartConfig · tabular-nums on data labels
[ ] Motion: transform/opacity only · reduced-motion fallback shows final state ·
    exit faster than enter · no correctness depending on animationend
```
