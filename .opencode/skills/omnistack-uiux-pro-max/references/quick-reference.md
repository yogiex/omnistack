# Quick Reference — Full Rule Index (10 Categories)

Load this file during UI review/audit passes, or when you need the complete checklist for one category beyond SKILL.md §3. Rule IDs are stable identifiers from ui-ux-pro-max (MIT).

## 1. Accessibility (CRITICAL)

`color-contrast` 4.5:1 normal text, 3:1 large text · `focus-states` visible ring 2–4px on every interactive control · `alt-text` meaningful images only · `aria-labels` icon-only buttons · `icon-context` decorative icons beside text → `aria-hidden="true"`; standalone meaningful icons → text alternative; icon controls → accessible name + state (selected/pressed/expanded) · `keyboard-nav` tab order = visual order · `form-labels` label[for] every input · `skip-links` skip-to-content on nav-heavy pages · `heading-hierarchy` sequential h1→h6 · `color-not-only` add icon/text to color signals · `dynamic-type` survive system text scaling without truncation · `reduced-motion` honor prefers-reduced-motion · `escape-routes` cancel/back in modals and multi-step flows · `keyboard-shortcuts` keep system/a11y shortcuts working; drag needs keyboard alternative · WCAG 2.2: `focus-not-obscured` (sticky UI must not cover focus), `focus-not-obscured-enhanced`, `focus-appearance` (≥2px perimeter, 3:1 state contrast), `dragging-alternative`, `web-target-size` (24×24 CSS px or documented exception), `consistent-help` (help in same relative order everywhere), `redundant-entry` (never re-ask same info in one process), `accessible-authentication` (paste + password managers allowed; non-cognitive path offered) · `auto-rotation-controls` carousels need pause/stop; stop on focus/hover/reduced-motion · `contextual-live-badge-updates` announce full contextual phrase ("3 items in cart"), atomic status region, never a bare number

## 2. Touch & Interaction (CRITICAL)

`touch-target-size` web ≥24px CSS (WCAG AA); iOS 44pt / Android 48dp; extend hit area beyond visual bounds · `touch-spacing` ≥8px gap between targets · `hover-vs-tap` click/tap primary, hover never required · `loading-buttons` disable + spinner during async · `error-feedback` near the problem · `cursor-pointer` all clickables (web) · `gesture-conflicts` no horizontal swipe on main content · `tap-delay` `touch-action: manipulation` · `standard-gestures` don't redefine platform gestures · `press-feedback` visual response within 80–150ms · `haptic-feedback` confirmations only, not every tap · `gesture-alternative` visible controls for critical actions, never gesture-only · `no-precision-required` no pixel-perfect taps · `swipe-clarity` swipes need affordance hint · `drag-threshold` movement threshold before drag starts

## 3. Performance (HIGH)

`image-optimization` WebP/AVIF + srcset/sizes · `image-dimension` width/height or aspect-ratio → CLS prevention · `font-loading` font-display swap/optional + reserve space · `font-preload` critical fonts only · `critical-css` above-the-fold first · `lazy-loading` dynamic import non-hero components · `bundle-splitting` by route/feature · `third-party-scripts` async/defer, audit regularly · `reduce-reflows` batch DOM reads then writes · `content-jumping` reserve space for async inserts (badges, validation text, media) · `lazy-load-below-fold` loading="lazy" · `virtualize-lists` virtualize at 50+ items · `main-thread-budget` ~16ms/frame for 60fps · `progressive-loading` skeletons over blocking spinners for >1s waits · `input-latency` <100ms · `tap-feedback-speed` feedback within 100ms of tap · `debounce-throttle` scroll/resize/input handlers · `offline-support` offline messaging (PWA) · `network-fallback` degraded mode for slow networks

## 4. Style Selection (HIGH)

`style-match` product type drives style (see SKILL.md §5) · `consistency` one system across pages · `no-emoji-icons` SVG only · `color-palette-from-product` industry-appropriate palette · `effects-match-style` shadows/blur/radius align with chosen style · `platform-adaptive` respect platform idioms · `state-clarity` hover/pressed/disabled visually distinct but on-style · `elevation-consistent` one shadow scale (sm/md/lg/xl), no random values · `dark-mode-pairing` design both themes together · `icon-style-consistent` one set, stroke width, corner radius · `system-controls` prefer native primitives · `blur-purpose` blur signals dismissal (modals), not decoration · `primary-action` ONE primary CTA per screen; secondaries subordinate

## 5. Layout & Responsive (HIGH)

`viewport-meta` device-width, zoom never disabled · `mobile-first` enhance up with md:/lg:/xl: · `breakpoint-consistency` systematic (375/768/1024/1440) · `readable-font-size` ≥16px body mobile (avoids iOS auto-zoom) · `line-length-control` 35–60 chars mobile, 60–75 desktop · `horizontal-scroll` never · `spacing-scale` 4px/8px increments · `touch-density` comfortable, no mis-taps · `container-width` consistent max-w (6xl/7xl) · `z-index-management` layered scale (0/10/20/40/100/1000) · `fixed-element-offset` fixed bars reserve padding · `scroll-behavior` no nested scroll conflicts · `viewport-units` min-h-dvh over 100vh · `orientation-support` landscape stays operable · `content-priority` core content first on mobile · `visual-hierarchy` via size/spacing/contrast, not color alone · `compact-label-overflow` badge/chip/tag semantics from use; truncation disclosed accessibly · `chip-collection-reflow` wrap before shrinking labels; +n overflow as operable disclosure

## 6. Typography & Color (MEDIUM)

`line-height` 1.5–1.75 body · `line-length` 65–75 chars · `font-pairing` heading/body personalities match · `font-scale` modular scale (12/14/16/18/24/32) · `contrast-readability` dark-on-light body · `text-styles-system` use type roles (display/headline/title/body/label) · `weight-hierarchy` headings 600–700, body 400, labels 500 · `color-semantic` semantic tokens, never raw hex in components ⭐ OmniStack law · `color-dark-mode` desaturated/lighter tonal variants, NOT inverted colors; test contrast separately per theme · `color-accessible-pairs` fg/bg pairs verified 4.5:1 (AA) or 7:1 (AAA) · `color-not-decorative-only` functional color includes icon/text · `truncation-strategy` prefer wrap > ellipsis > expand · `letter-spacing` default tracking; no tight tracking on body · `number-tabular` tabular figures for data columns/prices/timers (prevents shift) · `whitespace-balance` whitespace groups related, separates sections · `heading-line-balance` text-wrap: balance as progressive enhancement, never force line breaks · `long-token-wrapping` overflow-wrap: anywhere + min-inline-size: 0 on shrinkable flex/grid children; never break-all on prose

## 7. Animation (MEDIUM)

`duration-timing` shared motion tokens by distance/complexity/platform/context — no universal ms cutoff · `transform-performance` transform/opacity only · `loading-states` match expected wait; no flashing spinner for instant work, no unexplained long waits · `excessive-motion` 1–2 key elements per view max · `easing` decelerate entering, accelerate leaving, linear for constant-rate · `motion-meaning` cause-effect, not decoration · `state-transition` animate smoothly, never snap · `continuity` spatial continuity across transitions · `parallax-subtle` sparing + reduced-motion safe · `spring-physics` prefer spring curves · `exit-faster-than-enter` exit ≈60–70% of enter duration · `stagger-sequence` 30–50ms/item, ≤8 items · `shared-element-transition` hero continuity between screens · `interruptible` tap/gesture cancels immediately · `no-blocking-animation` input never blocked · `fade-crossfade` content replacement in same container · `scale-feedback` press scale 0.95–1.05, restore on release · `gesture-feedback` real-time finger tracking · `hierarchy-motion` enter-from-below = deeper, exit-upward = back · `motion-consistency` unified tokens globally · `opacity-threshold` fade fully or stay visible; nothing lingers below 0.2 opacity · `modal-motion` modals animate from trigger source · `navigation-direction` forward left/up, backward right/down · `layout-shift-avoid` animations never cause CLS · `cancellable-state-transitions` rapid changes cancel prior motion, set final state directly, correctness NEVER depends on animationend

## 8. Forms & Feedback (MEDIUM)

`input-labels` visible, never placeholder-only · `error-placement` specific error below field + aria-describedby · `submit-feedback` loading → success/error · `required-indicators` asterisk/(required) · `empty-states` helpful message + action · `toast-dismiss` 3–5s auto-dismiss · `confirmation-dialogs` destructive needs confirm · `input-helper-text` persistent helper below complex inputs · `disabled-states` reduced opacity 0.38–0.5 + cursor + semantic attr · `progressive-disclosure` reveal complexity gradually · `inline-validation` validate on blur, error after user finishes · `input-type-keyboard` semantic types trigger right keyboard · `password-toggle` show/hide · `autofill-support` autocomplete attributes correct · `undo-support` undo toast for destructive/bulk actions · `success-feedback` brief visual confirmation · `error-recovery` cause + fix path, never bare "Invalid input" · `multi-step-progress` step indicator + back navigation · `form-autosave` long forms save drafts · `sheet-dismiss-confirm` confirm discarding unsaved changes · `error-clarity` cause + how to fix · `field-grouping` fieldset/legend logical groups · `read-only-distinction` ≠ disabled visually AND semantically · `focus-management` failed multi-error submit → focus error summary; else first invalid field · `error-summary` focusable summary top, items link to fields, inline errors retained · `touch-friendly-input` mobile inputs ≥44px height · `destructive-emphasis` danger red + spatially separated from primary actions · `toast-accessibility` never steal focus; aria-live="polite" · `aria-live-errors` role="alert"/live region for form errors · `contrast-feedback` error/success colors also pass 4.5:1 · `timeout-feedback` timeout shows retry option

## 9. Navigation Patterns (HIGH)

`bottom-nav-limit` ≤5 items, icons + labels · `drawer-usage` secondary nav only · `back-behavior` predictable; preserve scroll/state · `deep-linking` key screens URL-reachable · `nav-label-icon` always icon + text label · `nav-state-active` current location highlighted · `nav-hierarchy` primary vs secondary clearly separated · `modal-escape` clear close affordance; swipe-down dismiss mobile · `search-accessible` reachable top bar/tab + recent queries · `breadcrumb-web` at 3+ depth levels · `state-preservation` back restores scroll/filter/input · `gesture-nav-support` no conflict with system gestures · `tab-badge` sparse unread indicators, cleared on visit · `overflow-menu` overflow instead of cramming · `bottom-nav-top-level` top-level screens only, never nested sub-nav · `adaptive-navigation` ≥1024px prefers sidebar; small screens bottom/top nav ⭐ OmniStack dashboard layout · `back-stack-integrity` never silently reset stack/jump home · `navigation-consistency` placement identical across pages · `avoid-mixed-patterns` don't mix Tab+Sidebar+BottomNav at same hierarchy level · `modal-vs-navigation` modals never carry primary nav flows · `focus-on-route-change` move focus to main content after route change (screen readers) · `persistent-nav` core nav reachable from deep pages · `destructive-nav-separation` logout/delete separated from normal nav · `empty-nav-state` explain unavailability instead of silent hiding

## 10. Charts & Data (LOW priority but OmniStack-relevant for FinOps)

`chart-type` trend→line, comparison→bar, proportion→pie/donut (≤5 slices) · `color-guidance` accessible palettes, avoid red/green-only pairs · `data-table` table alternative for screen readers · `pattern-texture` patterns/shapes supplement color · `legend-visible` near chart, clickable to toggle series · `tooltip-on-interact` exact values on hover/tap; keyboard-reachable too · `axis-labels` units + readable scale, no truncated/rotated mobile labels · `responsive-chart` simplify on small screens (horizontal bar, fewer ticks) · `empty-data-state` "No data yet" + guidance, never blank chart · `loading-chart` skeleton while loading, never empty axis frame · `animation-optional` entrance respects reduced-motion; data readable immediately · `large-dataset` aggregate/sample at 1000+ points; drill-down for detail · `number-formatting` locale-aware axes/labels · `touch-target-chart` interactive elements ≥44pt tap area · `no-pie-overuse` >5 categories → bar chart · `contrast-data` lines/bars vs bg ≥3:1; data labels ≥4.5:1 · `direct-labeling` small datasets label directly · `sortable-table` aria-sort on sortable columns · `gridline-subtle` low-contrast gridlines (gray-200) · `focusable-elements` chart points keyboard-navigable · `screen-reader-summary` text summary of key insight via aria-label · `error-state-chart` load failure shows retry, not broken chart · `export-option` CSV/image export for data-heavy products · `drill-down-consistency` back-path + hierarchy breadcrumb maintained · `time-scale-clarity` time granularity labeled and switchable
